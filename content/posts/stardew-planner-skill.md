我非常喜欢星露谷物语这款游戏，在 Nintendo Switch 有 [400+ 小时的游戏时长](https://gist.github.com/sigming/4aa566c004d4baac8561a36ae02bc2ea#file-nintendo-switch-box)，现在有两个存档：一个单人，一个跟女朋友一起玩的双人农场。

## 单人存档
在玩单人农场的时候，前期主要还是升级工具、技能，以及赚钱，农场布局随心所欲，等后期我想给农场来一个舒服的布局并基本结档的时候，尝试自己规划了一下，大致的功能分区划分好之后，细节的装修实在是太难搞定，在 B 站找了别人分享的布局图，然后一点一点数格子布置，这个过程实在是有些痛苦，因为我要反复去查某个物体具体是什么，如何获取，简单的物体还好点，一些平常不接触的家具、地板、灯具以及装饰品，翻找比较麻烦。另一个问题就是对于大量地板栏杆等物体，无法估算具体的消耗量，虽然后期不缺钱，但我也不想买太多，这个过程让我十分头疼，最终手搓出来的效果：

## 双人存档
在开始双人农场游戏后，钓鱼，种地，逐渐的我们的资金和技能都提升的差不多了，是时候开始新的规划，在小红书、B 站等平台看到了很多优秀、美观的设计，但一想单人农场的经历，头就已经大了，迟迟无法推进这件事。

## Agent SKILL
[GPT 6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra) 发布后，社交媒体上有大量的博主分享它在 PCB 设计、3D 建模等场景的使用，我产生了一个新的想法，能否利用 GPT 6 来辅助我进行星露谷物语农场的布局规划，减少手动查找 Wiki 和计算物料数量。

GPT 6 Astra 对这个 skill 做了以下设计：
1. 收集整理物品素材，这部分主要是采用 `stardew.info` 、`stardewplan.com` 以及星露谷物语官方 Wiki 上的图片素材，生成所有物品的图片、大小和占位、分类等信息，在 `data/planner` 目录保存物品目录、中英文名称、精灵图、图集、作用范围数据。
2. 整理地图素材，同上来源，整理所有官方原版地图信息，在 `data/maps` 保存地图尺寸、季节背景、默认建筑、固定地标、摆放限制及 TMX 地图源文件
3. 记录原文件的来源等信息，确保素材的可追溯性，在 `data/recognition` 目录下保存识别分类、卡片位置、补充参考、素材来源与覆盖审计信息。
4. 准备图鉴合集，由于 AI 输入图片的限制，这里我们将同一类别的物品和信息进行拼接，提供一些物品的变体形态以及易混淆的物品区分，尽量让一个大类的物品信息能够在一张图中完整展示，这样 AI Agent 可以只读取一张图获得一个大类的物品内容，保存在 `assets/recognition` 下
5. 编写操作脚本，布局信息存储我们这里选择使用 JSON 格式，而让 AI 直接编写 JSON 容易出现上下文过长、格式错误问题，所以我们设计了一个统一的操作脚本 `scripts/layout.py`，AI Agent 可以调用脚本完成布局生成、更新、检查、渲染等操作，同时也提供了诸如物品搜索、打包等其他辅助脚本。
6. 编写 SKILL.md，指导 AI Agent 如何使用上述素材和脚本完成农场布局设计、复刻和优化。

写完后我在小红书找了[一位博主分享的农场布局](https://www.xiaohongshu.com/explore/687126a5000000000b02f250?xsec_token=ABU8mFZymPh2mVqCwWCtAg1VB6u3Q7orWzTcLg4iXUno0=&xsec_source=pc_user)，让 GPT 6 Astra 尝试复刻，在这个过程中发现了太多的问题：
1. AI 比较容易混淆一些物体，比如把[蘑菇树桩](https://zh.stardewvalleywiki.com/%E8%98%91%E8%8F%87%E6%A0%91%E6%A1%A9)误认为是[圆木段](https://zh.stardewvalleywiki.com/%E5%9C%86%E6%9C%A8%E6%AE%B5)，还有疯狂的尝试寻找玩家角色到底是个什么物品，最终我在图鉴里增加了可忽略物品的图鉴：玩家角色、玩家小孩、马匹、宠物等，减少了这些干扰因素。
2. 最初的设计里，一个物品占据地面后，不允许其他物品覆盖，事实上这是错误的，例如住宅的走廊上可以放置家具、小桶等，温室前面自带的砖块也可以被地板覆盖等等，为此我们调整了判断规则，增加了一些特殊情况
3. 参考图片可能包含一些物品的激活状态，而我们的素材是默认状态，例如篝火的开启、鱼塘里的鱼类导致的池水颜色变化，不同作物、超大作物的生长阶段等，如果把所有这些可能变化的物品（尤其是作物）塞进图鉴，那图鉴的数量会急剧增加，AI 也难以处理，这里我们做了一些详细的简化规则，比如将作物统一为成熟的草莓，超大作物统一为超大南瓜等等，降低了图鉴的复杂度。
4. 被遮挡的道路、地板，地板上可以放置其他物品，有些路段被树木、物品遮挡，这部分在 skill 里规定让 AI 根据周围环境判断是否铺设地板。
5. 洒水器、蜂巢、稻草人、祝尼魔小屋的作用范围，我们设计了专门的规则，让 AI 在布局时能够正确计算这些物品的影响区域，避免覆盖或遗漏，但如果参考图本身就存在未能完全覆盖作物的部分，AI 会在交付时说明此类情况，方便调整
6. 布局完成后需要来一次完整的检查，这里检查如果都交给主会话会非常慢且容易读取太多图片，我们设计了地图切分 + Sub-agent 任务，每个 Sub-agent 负责检查地图的一部分，最终汇总检查结果，提高了检查效率和准确性。

## 使用方法
使用 npx 安装在某项目下或者全局都可以，确保你已经安装了 Python 3.12+、uv、NodeJS 和 Git
```bash
npx skills add sigming/stardew-planner-skill --skill stardew-planner-skill -a codex -a claude-code
```

然后直接把需求或者参考图片发给 AI Agent 开始布局规划，注意你的 Token 余量 😆

遇到问题欢迎在 [GitHub Discussions](https://github.com/sigming/stardew-planner-skill/discussions) 中提问、[提交 issues](https://github.com/sigming/stardew-planner-skill/issues)，或者[创建 Pull Request](https://github.com/sigming/stardew-planner-skill/pulls)。

## 推荐实施步骤
拿到 AI Agent 生成的布局简图和物料清单后，推荐按照下面的流程操作装修：
1. 先根据给出的清单准备物料，地板、栏杆这种高消耗物品可以多买十几二十个，免得短缺
2. 确定建筑物位置，找罗宾移动或建造，在建造过程中开始铺地板和道路，多对照实施简图和渲染图，找准参考点，铺错了没关系，拿十字镐敲掉，路铺好之后，农场大致的分区就有了
3. 开始逐个分区装修，如果需要种植果树，一定要清空周围八格，否则果树永远长不大，等果树成熟后再补齐周围八格的物品，普通树木也要在这时候种植上，有条件的话可以给普通树木施加树肥，提高生长效率，后期还可以将醋倒在树上阻止生长苔藓
4. 逐个分区检查细节，放置家具等装饰品
5. 最后种植草，草的加入可以让农场看起来更丰富和自然
6. 最后可以根据自己的喜好微调
7. 开始养老
